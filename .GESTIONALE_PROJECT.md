# Gestionale Paola - Backend Quarkus

**Repository:** `saas-gestionale`
**Frontend servito:** `paola_gestionale` (app nativa SwiftUI macOS/iOS)

## Stack Tecnologico
- **Framework:** Quarkus 3.39.5
- **Linguaggio:** Java 21
- **Database:** PostgreSQL (produzione/remoto), H2 (dev/test)
- **ORM:** Hibernate ORM Panache (active record)
- **Migrazioni:** Liquibase 4.20.0
- **API:** Quarkus REST + Jackson, OpenAPI/Swagger, Hibernate Validator, Health
- **Build:** Maven con wrapper

## Struttura del Progetto

```
src/main/java/com/pirris/
├── model/        # 13 entity Panache (+ Base/Audited/Tenant*Model, enums/ con converter)
├── dto/          # DTO del contratto HTTP, raggruppati per view/area (overview/, auth/)
├── repository/   # accesso dati tenant-aware (TenantRepository + concreti)
├── security/     # TenantContext (studio corrente dal JWT)
├── service/      # logica di business (AuthService + stub in costruzione)
└── resource/     # REST per view: interfacce + impl/, error/
src/main/resources/
├── application.properties
└── db/changelog/db.changelog-master.xml   # schema Liquibase (fonte di verità)
```

## Database (13 tabelle Liquibase: 2 identità + 11 dominio)

Identità / multi-tenant:

| Tabella | Descrizione |
|---------|-------------|
| `studio` | Tenant: studio isolato |
| `account` | Login (email, hash BCrypt, ruolo admin/user), appartiene a uno studio |

Dominio (ognuna con `studio_id`):

| Tabella | Descrizione |
|---------|-------------|
| `training_service` | Servizi di training offerti |
| `service_rate` | Tariffe e durate per servizio |
| `client` | Anagrafica clienti con note mediche e preferenze di appuntamento integrate |
| `training_session` | Appuntamenti; occorrenza di corso se `course_id` valorizzato |
| `lesson_package` | Pacchetti lezioni/tempo prepagati |
| `session_participant` | Partecipanti alle sessioni (prezzo, pacchetto, pagato, nero) |
| `unavailability` | Blocco calendario trainer |
| `invoice` | Fatture clienti |
| `expense` | Spese aziendali/personali |
| `course` | Template di corsi settimanali di gruppo |
| `course_participant` | Iscrizioni ai corsi |

## Scelte di design chiave
- **Multi-tenant** (tenant = studio): isolamento **applicativo** via `studio_id` + `TenantRepository`/`TenantContext` (deny-by-default), non `@TenantId` di Hibernate (gap Quarkus con discriminator). Auth JWT RS256 + BCrypt; prefisso REST `/api` via `quarkus.rest.path`.
- **Contabilità derivata**: nessuna tabella ledger. Saldi/incassi calcolati da sessioni completate + pacchetti + spese. `saldo = addebiti netti − incassi netti`.
- **Crediti pacchetto derivati**: nessuna tabella di consumo. Residui = `capacity − partecipanti con quel pacchetto e sessione completata`.
- **Corsi come sessioni**: `course` è il template; le occorrenze sono `training_session` con `course_id`.
- **Enum tipizzati** via `AttributeConverter` (valore `raw()` in colonna `*_raw`).
- **Importi in centesimi** (`long`), mai float. Soft delete via `is_archived`.
